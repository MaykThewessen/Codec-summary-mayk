Data formats / measured, not folklore

Which format wins,
and exactly where

Dutch grid work produces three kinds of file: price timeseries, power flow results, and weather. The format argument for all three collapses into two questions: how you will read the file back, and how long it has to survive and for whom. Position on those two axes decides the winner, and the losers are not where most people expect.

The headline

Three of forty-one columns

The x-axis of the map, measured. Each format gets three dots: the time to read the whole file into a dataframe, the time to read three columns out of it, and the time to answer one filtered query. A columnar format lets the second and third dots move left. A row format does not: the bytes have to be parsed in order whatever you asked for.

The Feather question

Is it really RAM saved to disc?

Yes, with three conditions. An uncompressed Arrow IPC file has the same byte layout on disk that Arrow uses in memory, so the kernel can map it and nothing is decoded or copied. The conditions: the file must be uncompressed, you must stay in Arrow rather than converting to pandas, and a zero-copy numpy view only exists for a fixed-width column with no nulls in a single chunk. Break any of them and you are back to a normal read.

The caveat that flips a ranking

When the file is not already in memory

Every other timing on this page is warm: the file was just written, so it is in the page cache and the measurement is decode cost, not disk cost. That is the right model for a workstation working through the same files all afternoon. It is the wrong model for a file coming off a network share or a cold machine, and there the file size stops being a storage question and becomes the read time.

A confusion worth clearing up

Format and engine are separate choices

"Polars is faster than pandas" and "Parquet is faster than CSV" are answers to different questions, and mixing them up produces most of the bad advice on this subject. The same two files at the large scale, read by all three engines into a dataframe.

Operational

What to actually type

Every path below keeps timestamps tz-aware in UTC, which is the one convention that prevents the largest class of silent bug in this work. Convert to Europe/Amsterdam at the display boundary and nowhere else.

Project storage and archive: Parquet

# write: zstd is the default worth having, index=False keeps the schema honest
df.to_parquet("data/prijzen.parquet", compression="zstd", index=False)

# read the whole thing
df = pd.read_parquet("data/prijzen.parquet")

# read three columns out of forty: this is the entire point
df = pd.read_parquet("data/runs.parquet",
                     columns=["snapshot", "p_mw_MVL_KIJ_380", "loading_pct_MVL_KIJ_380"])

# push the predicate down so unmatched row groups are never decompressed
import pyarrow.parquet as pq
tbl = pq.read_table("data/prijzen.parquet",
                    filters=[("zone", "==", "NL")])
df = tbl.to_pandas()

# partition when the filter column is always the same one
df.to_parquet("data/prijzen/", partition_cols=["zone"], compression="zstd")

Scratch and interprocess: Feather / Arrow IPC

# uncompressed on purpose: this is the file you want to memory-map
df.to_feather("run/state.arrow", compression="uncompressed")
df = pd.read_feather("run/state.arrow")
df = pd.read_feather("run/state.arrow", columns=["snapshot", "p_mw_MVL_KIJ_380"])

# the zero-copy path: nothing is decoded, nothing is copied
import pyarrow as pa, pyarrow.ipc as ipc, pyarrow.compute as pc
tbl = ipc.open_file(pa.memory_map("run/state.arrow")).read_all()
mean_mw = pc.mean(tbl["p_mw_MVL_KIJ_380"]).as_py()

# a numpy view over the file, no allocation. raises if it cannot be zero-copy.
arr = tbl["p_mw_MVL_KIJ_380"].combine_chunks().to_numpy(zero_copy_only=True)

# tbl.to_pandas() copies the lot. only do it when you need pandas.

Queries: DuckDB, over Parquet or over its own file

# no import step. duckdb reads the parquet you already have.
import duckdb
con = duckdb.connect()
con.execute("SET TimeZone='UTC'")            # do this on every connect
df = con.sql("""
    SELECT date_trunc('day', timestamp) AS dag,
           zone,
           avg(price_eur_mwh) AS gem_prijs
    FROM 'data/prijzen.parquet'
    WHERE zone = 'NL'
      AND timestamp >= TIMESTAMPTZ '2023-01-01 00:00:00+00'
    GROUP BY 1, 2 ORDER BY 1
""").df()

# a persistent database when you want indexes, joins and updates
con = duckdb.connect("grid.duckdb")
con.execute("SET TimeZone='UTC'")
con.execute("CREATE TABLE prijzen AS SELECT * FROM 'data/prijzen.parquet'")
con.execute("CREATE INDEX ix ON prijzen (zone, timestamp)")

# store TIMESTAMPTZ, never TIMESTAMP, or the zone is gone on the way in
con.execute("ALTER TABLE prijzen ALTER timestamp TYPE TIMESTAMPTZ")

Polars, same files

import polars as pl

pl.read_parquet("data/prijzen.parquet")
pl.read_parquet("data/runs.parquet", columns=["snapshot", "p_mw_MVL_KIJ_380"])
pl.read_ipc("run/state.arrow", memory_map=True)          # the mmap path

# scan_* is lazy: projection and predicate are pushed into the file
(pl.scan_parquet("data/prijzen.parquet")
   .filter(pl.col("zone") == "NL")
   .group_by_dynamic("timestamp", every="1d")
   .agg(pl.col("price_eur_mwh").mean())
   .collect())

Method

How these numbers were produced, and where not to trust them

The machine was busy

Reads are warm

Every timed read follows an untimed read of the same file, so the page cache is loaded and the number is decode cost rather than disk cost. The cold-cache section above is the correction. On a cold machine or a network share, file size and read time are much closer to the same measurement.

A read means a pandas DataFrame

Every reader returns a pandas DataFrame, including the DuckDB ones, so the Arrow-to-pandas conversion is inside every timing. That is the honest cost of using the format from pandas, but it flatters nothing and it penalises DuckDB slightly, since a query you consume as Arrow or as a partial aggregate never pays it.

What is not measured

Scripts and raw measurements live in the repository beside this page, so every figure can be regenerated or argued with. The corpora are generated, not fetched: they are shaped like Dutch grid data but they are not anyone's real data.
